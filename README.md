# Bitcoin / Gold Explorer

An interactive research workspace by **Sasa Wu**, extending a FIT5145 Foundations of Data Science assignment into a reproducible data-analysis side project.

Compare Bitcoin, a gold price proxy and the US Dollar Index through normalised performance, drawdowns, return volatility, trailing correlations and a descriptive dollar-tail analysis.

> **The bundled dashboard uses explicitly labelled synthetic data.** No real historical prices were accessible while packaging this release. The original assignment's Google Drive CSV could not be retrieved, and local outbound access to Yahoo Finance was unavailable. No reported market findings are copied into the interface. Import your own observed prices or run the R refresh script to replace the simulation with a documented snapshot.

## Open the app

Open **`dist/index.html`** in Chrome. No installation, server or build step is required for the browser application. Optional local server:

```sh
python3 -m http.server 8000 --directory dist
```

Then visit http://localhost:8000. Prices stay in browser memory; imports disappear on reload. The only optional external UI request is Google Fonts, with local fallbacks.

## What works

- Adjustable observation range: all, three years, one year, six months, or custom dates.
- Normalised price indices, base 100, with linear/log scale toggle and an observation inspector.
- In-range drawdowns, total price changes and sample interval volatility.
- Pearson return-correlation matrix and 30/60/90-observation trailing correlations for all asset pairs.
- A dollar stress lab selecting the upper 5/10/20% tail of DXY log returns, restricted to positive returns.
- CSV import with complete-date alignment, validation and source notes.
- Loaded-price CSV, selected-tail return CSV, and JSON analysis exports including the actual selected prices and methods.
- A corrected R reference engine, a data-refresh pipeline and an R Markdown report template.
- Automated tests, including numeric parity between R and JavaScript.

## Get real historical data

From the project root, install R packages once in R or RStudio:

```r
install.packages(c("tidyquant", "jsonlite"))
```

Then run in your terminal:

```sh
Rscript --vanilla R/refresh_data.R
```

On macOS you can also run `sh Refresh-Data.command` from Terminal. The script changes to its own project directory, refreshes prices and opens the app on success. Terminal avoids macOS treating the downloaded command file as an untrusted double-click app.

Defaults are **2015-01-01 through 2026-05-24 inclusive**, matching the original Rmd's intended interval. These are requested bounds; the actual retained observation dates are computed and displayed. Change them explicitly if desired:

```sh
Rscript --vanilla R/refresh_data.R --from 2020-01-01 --to 2025-12-31
```

Source symbols:

| Explorer label | Yahoo symbol | Interpretation |
| --- | --- | --- |
| Bitcoin | BTC-USD | Bitcoin USD price series |
| Gold | GC=F | Gold futures proxy; not physical or spot gold |
| DXY | DX-Y.NYB | US Dollar Index level; not an investable portfolio |

The pipeline uses Yahoo's `adjusted` field, rejects missing symbols and validates all retained prices. It saves raw source rows, aligned prices, metadata, calculated results, file MD5 and `sessionInfo()` under `analysis-output/`. Only after successful analysis does it replace `dist/data.js`. A failed download leaves the previous browser dataset intact. This is an on-demand historical snapshot, **not a live feed** or scheduled service. Vendor availability and rate limits can prevent refresh.

After refresh, reload the browser. The top banner changes from **ILLUSTRATIVE DEMO** to the appropriate snapshot source. Commit the new `dist/data.js` if you intend to publish the snapshot; check your data provider's redistribution terms first.

A fixed date range does not guarantee identical future downloads. Keep the saved CSV, source metadata and package environment if exact reproducibility matters.

## Use your own CSV

In **Data & methods**, enter a source note and upload a wide-format CSV:

```csv
date,bitcoin,gold,dxy
2024-01-02,100,100,100
2024-01-03,110,101,99
2024-01-04,99,102,101
```

The numbers above and `examples/prices.csv` are **synthetic calculation fixtures**, not historical quotes. Header names are case-insensitive. Dates must be unique ISO dates; prices must be positive finite numbers, without currency symbols or thousands separators. Empty asset fields drop that date. Invalid prices, duplicate dates, bad headers and malformed field counts reject the entire file. UTF-8 BOM and quoted fields are supported. Extra columns are ignored. Limit: 5 MB and 20,000 rows.

For an offline snapshot generated by R from your CSV:

```sh
Rscript --vanilla R/refresh_data.R --input /absolute/path/to/your-prices.csv
```

This labels the source as user-imported and does not independently verify the instrument or timestamps. Imported data need not use Yahoo symbols; ensure the three fields represent the intended assets.

## Methodology

1. **Alignment:** keep complete common observed dates. No forward-fill, interpolation or assumed synthetic weekend closes. This is not a verified exchange calendar: an absent date cannot be identified without an external expected-date calendar. The largest gap is reported.
2. **Returns:** `log(P[t]) - log(P[t-1])` between consecutive common observations. A Monday observation may span Friday-to-Monday. These are not uniform 24-hour crypto returns.
3. **Volatility:** sample standard deviation of those log returns, divisor `n - 1`. No annualised Sharpe ratios, volatility or trading-day assumptions are introduced.
4. **Correlation:** Pearson correlation of returns consistently for static and rolling calculations. Full trailing windows only. Zero variance or insufficient samples produce an unavailable value. Rolling chart axes remain [-1, +1].
5. **Performance:** last price / first price - 1; indices rebased to 100. Price changes exclude transaction costs, financing and investment implementation effects.
6. **Drawdown:** price / running maximum - 1, calculated only within the selected range. This may differ from a drawdown measured from an earlier peak.
7. **Dollar tail:** use the selected sample's linearly interpolated (type-7) quantile; retain DXY returns at or above it and strictly above zero. Ties can change the fraction selected. Compare conditional mean log returns, negative-return shares and correlations with DXY.
8. **Extreme observations:** retained, never automatically winsorised or declared source errors.

Calendar-date joins do not eliminate differences in market close times. Yahoo continuous futures can introduce roll effects. A DXY-tail subset does not test protection against equity crashes or every crisis. Correlations have no uncertainty estimates in this version. No causality, trading signal, safe-haven classification or allocation recommendation is produced.

### Changes from the assignment

| Original issue | Portfolio implementation |
| --- | --- |
| Report and Rmd used different stated date periods | One explicit requested period; actual retained coverage shown |
| Static correlations used prices, rolling correlations used returns | Both consistently use log returns |
| Forward-fill created zero returns on non-trading dates | Complete observed-date intersection, no filling |
| Findings and data-quality claims were hard-coded | Findings, missing counts and summaries derive from the loaded data |
| Rolling-correlation chart clipped the range | Axis fixed at the valid [-1, +1] bounds |
| Outlier detection followed by unconditional quality claims | No automatic quality verdict or outlier deletion |
| Advanced models were discussed in the report | UI clearly states implemented vs unimplemented methods |
| Fixed end date described as a reproducibility guarantee | Save snapshots, metadata and actual package versions |

DCC-GARCH, Markov-switching, Granger/Toda-Yamamoto tests, GSADF, ETF flows, portfolio optimisation and predictive modelling are **not implemented**.

## Tests

JavaScript, Node.js 18+:

```sh
node --test tests/analytics.test.js
```

R reference calculations:

```sh
Rscript --vanilla tests/test_reference.R
```

Cross-language numeric agreement, requires R and `jsonlite`:

```sh
node --test tests/cross-language.test.js
```

The checks cover hand-calculated returns and drawdowns, sample volatility, correlation edge cases, trailing-window causality in the computational sense (no look-ahead), date handling, missing observations, invalid prices, dollar-tail selection and agreement between the two implementations. This does not validate a financial forecasting model.

## Corrected R Markdown report

Requires `rmarkdown`, `knitr` and Pandoc (usually supplied by RStudio). Example from project root:

```r
rmarkdown::render("R/analysis.Rmd", params = list(csv = normalizePath("analysis-output/prices.csv")))
```

The default small example is synthetic. The R functions and offline data-generation pipeline were executed during development. This environment lacked Pandoc, so rendering the Rmd to HTML was not verified. Browser visual QA was also unavailable in the development environment.
